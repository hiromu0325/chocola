テキスト差し替え・多言語化のしくみ　運用手順
　2026/09/13
================================================================

■0. ひとことで

　ゲーム内の文章は、もうコードにもシーンにも属していません。
　Excel（原本）→ ビルド時に変換 → 実行時にIDで引く、という流れです。

　　進行/テキスト/GameText.xlsx        ← 書き手が編集する原本
　　進行/文書/ja/<ID>.txt              ← 長文の本文（テキストエディタで編集）
　　　　↓ Unityメニュー「テキストを取り込む」／ROMビルド時に自動
　　Assets/Resources/GameText.asset    ← ゲームが読む形（自動生成。手で触らない）
　　　　↓ 実行時
　　画面の文章

　文章を直してもシーン再生成は不要です。取り込み直してUnityを再生するだけ。
　シーンファイルの差分も出ないので、Gitが汚れません。

----------------------------------------------------------------
■1. 差し替えの手順（いつもの作業）
----------------------------------------------------------------

　1) 進行/テキスト/GameText.xlsx を開く
　2) ja 列を本番テキストで上書きする
　　 ・セルが「@file:doc_analysis.spec.body」なら、
　　 　進行/文書/ja/doc_analysis.spec.body.txt の中身を書き換える
　　 　（長文はぜんぶこの形。Excelに長文を詰め込まない）
　　 ・status 列を「仮」→「確定」に変えると進捗が見える（ゲームには影響しない）
　3) id 列は絶対に触らない（ゲーム側がこれで引いている）
　4) Unityメニュー Tools > EscapePrototype > Text > テキストを取り込む
　5) 再生して確認

　※原本が無い状態でも動きます。表に無いIDはコードの組み込み文が出るので、
　　差し替えは1件ずつ進められます（途中で文章が消えることはありません）。

----------------------------------------------------------------
■2. メニュー
----------------------------------------------------------------

　Tools > EscapePrototype > Text >
　　・テキストを取り込む（Excel → GameText.asset）
　　　　進行/テキスト/GameText.xlsx を読んでゲーム用データを作る。
　　　　原本が無ければファイル選択ダイアログが出る
　　・テキストシートを選んで取り込む … 別のファイルから取り込む
　　・現在のテキストを書き出す（TSV） … 今ゲームに入っている文章を全部吐き出す
　　・差し替え状況を確認する … 未登録ID・未使用ID・言語ごとの入力率を出す

　ROMビルド（build_rom.bat）は毎回、原本を自動で取り込んでから焼きます。
　取り込み忘れのままROMを配ることはありません。

----------------------------------------------------------------
■3. ID の付き方
----------------------------------------------------------------

　　種別/キー.フィールド

　　doc/<部屋>.<資料id>.name      資料の表示名（プロンプト用）
　　doc/<部屋>.<資料id>.title     手帳の見出し
　　doc/<部屋>.<資料id>.body      本文
　　doc/<部屋>.<資料id>.hint      拾得時の操作ヒント
　　doc/<部屋>.toy.*              終章の思い出のおもちゃ
　　echo/<残響id>.title / .body   残響の記録文
　　lock/<部屋>.<装置id>.title    装置の問題文（見出し）
　　　　　　　　　　　　.body     問題文（説明）
　　　　　　　　　　　　.option.0 選択肢（0から連番）
　　　　　　　　　　　　.step.0   配電盤の系統名
　　　　　　　　　　　　.row.0    ログ照合の表の行
　　　　　　　　　　　　.success_title / .success_body  正解時に手帳へ残る成果
　　　　　　　　　　　　.solved / .wrong / .require / .notenough  トースト
　　room/<部屋>.name / .chapter   部屋名・章ラベル
　　ui/<名前>                     トーストや操作プロンプトの定型文

　IDは部屋Idと資料Idから自動で決まります。シーンにID欄はありません。
　＝資料を増やしても、ビルダーで id を付ければ自動的に差し替え対象になります。

　ui/ の定型文には {0} などの差し込みがあります。翻訳時も同じ数だけ残してください。
　（例: 「『{0}』を手帳に綴じた」→「Filed 『{0}』 in the notebook」）

----------------------------------------------------------------
■4. 多言語化のやり方
----------------------------------------------------------------

　列を足すだけです。

　　id | kind | room | speaker | status | note | ja | en | zh-Hans | ko | …

　・見出しに書いた文字列がそのまま言語コードになります
　・管理列（id/kind/room/speaker/status/note/max）以外は全部「言語の列」扱い
　・空欄の言語は既定言語（いちばん左の言語＝ja）にフォールバックします
　　→ 翻訳が半分でもゲームは動きます
　・長文を言語ごとに分けたい場合は 進行/文書/<言語>/<名前>.txt に置きます
　　（無ければ 進行/文書/<名前>.txt が使われます）

　ゲーム内での切り替え:
　　EscapeProto.GameText.Language = "en";
　　EscapeProto.GameText.AvailableLanguages  … 選択肢の一覧（設定画面用）
　　※オプション画面への言語切替UIは未実装。必要になったら足します。

　【翻訳で注意すること】
　・資料ウィンドウは約33字×14行。日本語より英語のほうが行数が増えるので、
　　書き出し時に長すぎる本文は note 列に「（長い:要確認）」の印が付きます
　・フォント。現在は日本語フォントなので、中国語・韓国語を入れる場合は
　　字形の差（簡体字・ハングル）に対応したフォントの追加が必要です

----------------------------------------------------------------
■5. ROMを配ったあとに文章だけ直す
----------------------------------------------------------------

　実行ファイルの隣に GameText フォルダを作り、<言語>.tsv を置くと、
　その内容がゲーム内のテキストより優先されます。ビルドし直さずに校正できます。

　　RENASCITA.exe
　　GameText/ja.tsv     ← 1列目=ID、タブ、2列目=文面（改行は \n と書く）

　例:
　　room/ward.name	臨床病棟（第3）
